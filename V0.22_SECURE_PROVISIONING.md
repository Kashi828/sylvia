# SYLVIA v0.22 Beta — Secure Device Provisioning

## Goal

Reduce manual credential setup while avoiding the unsafe pattern of putting an
owner API token directly into firmware.

## Flow

1. Owner authenticates to SYLVIA.
2. Owner creates a short-lived provisioning claim for a device.
3. SYLVIA returns a one-time `provisioningId` and `claimCode`.
4. Device claims the code.
5. The provisioning service returns a device credential.
6. The device stores the credential securely.
7. Normal REST/MQTT device communication begins.

## Endpoints

### Create claim

`POST /api/v1/devices/provision`

Requires the device's existing bearer authorization.

### Claim

`POST /api/v1/devices/provision/claim`

Body:

```json
{
  "provisioningId": "...",
  "claimCode": "..."
}
```

Claims expire after 15 minutes and are single-use.

## Important beta limitation

The current beta's claim store is in-process and the returned credential is a
provisioning credential placeholder. Production v1.0 must persist claims,
rotate/revoke credentials, use TLS, and integrate with the actual device-token
store before this is considered production-grade provisioning.
