# SYLVIA v0.36 Beta — Durable Notifications & Event Subscriptions

v0.36 moves the notification center from an in-memory-only foundation toward durable storage.

## Durable storage
- `notifications` stores alert and webhook notification records.
- Read state survives server restarts when PostgreSQL is configured.
- `notification_preferences` stores the in-app notification preferences.
- Migration: `004_notifications.sql`.

## Compatibility
Without `DATABASE_URL`, SYLVIA keeps the v0.35 in-memory fallback so local development remains dependency-light.

## Event subscription foundation
The notification layer now treats alert and webhook activity as normalized event sources. This creates the foundation for project/device scoped subscriptions and future email/mobile push channels without coupling the core telemetry engine to a specific provider.

## APIs
Existing notification endpoints remain compatible:
- `GET /api/v1/notifications`
- `POST /api/v1/notifications/:id/read`
- `POST /api/v1/notifications/read-all`
- `GET/PATCH /api/v1/notifications/preferences`

## Production follow-up
v0.36 intentionally keeps source-event synchronization lightweight. A later release should introduce authenticated project/user ownership, database-backed alert events, subscription records, and background delivery workers.
