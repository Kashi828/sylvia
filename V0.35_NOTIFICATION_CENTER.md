# SYLVIA v0.35 Beta — Notification Center

## What changed
- Added an in-app Notification Center at the `Notifications` workspace.
- Alert events and webhook delivery results are normalized into one notification inbox.
- Added unread/read state and a `Mark all read` action.
- Added filters for all, unread, critical and warning notifications.
- Added in-app notification preferences for alerts, webhook results and critical-only mode.
- Added notification REST endpoints under `/api/v1/notifications`.
- The inbox refreshes every five seconds, matching the existing realtime beta workspaces.

## API
- `GET /api/v1/notifications?limit=100`
- `POST /api/v1/notifications/:id/read`
- `POST /api/v1/notifications/read-all`
- `GET /api/v1/notifications/preferences`
- `PATCH /api/v1/notifications/preferences`

## Architecture
Notifications are currently an in-memory beta foundation derived from the existing alert/event and webhook delivery stores. No external email or push provider is required. This keeps SYLVIA standalone while leaving a clean path for durable notification storage and email/mobile push in a later beta.

## Next
v0.36 can add durable notification persistence, event subscriptions and channel adapters without changing the user-facing inbox contract.
