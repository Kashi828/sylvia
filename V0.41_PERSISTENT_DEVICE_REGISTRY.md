# SYLVIA v0.41 Beta — Persistent Device Registry

## Purpose
The fleet registry introduced in v0.23 was runtime-only. v0.41 adds a PostgreSQL-backed registry so device lifecycle and presence metadata survive application restarts.

## Stored fields
- `device_id`
- `name`
- `lifecycle`
- `last_seen`
- `firmware`
- `transport`
- `created_at`
- `updated_at`

## Behavior
When `DATABASE_URL` is configured, the registry hydrates from PostgreSQL and mutations are upserted into `device_registry`. Without a database, the existing in-memory behavior remains available for local/demo use.

## Migration
Run:

```bash
npm run db:migrate
```

This applies `migrations/007_device_registry.sql` through the existing migration runner.

## Fleet APIs
`GET /api/v1/fleet` now hydrates persisted devices and marks online devices stale after 90 seconds without a heartbeat.

`POST /api/v1/fleet` persists newly registered devices.

`POST /api/v1/fleet/presence` persists heartbeat/presence metadata after device authentication.

`POST /api/v1/fleet/lifecycle` persists lifecycle transitions.
