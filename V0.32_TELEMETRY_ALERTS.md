# SYLVIA v0.32 Beta — Telemetry Alerts

Telemetry alerts add threshold-based event detection to the ingestion pipeline.

## Included
- Alert rules for `>`, `>=`, `<`, `<=`, `=`, `!=` numeric thresholds.
- Info, warning and critical severities.
- Per-rule cooldown/deduplication.
- Active rule state and acknowledgement.
- Alert event history (beta in-memory store).
- Telemetry ingestion evaluates matching rules and returns triggered alerts in the API response.
- REST endpoints for rule CRUD and alert events/acknowledgement.
- Alerts workspace in the dashboard.

## API
- `GET /api/v1/alerts/rules`
- `POST /api/v1/alerts/rules`
- `PATCH /api/v1/alerts/rules`
- `DELETE /api/v1/alerts/rules?id=<ruleId>`
- `GET /api/v1/alerts/events`
- `GET /api/v1/alerts/events?activeOnly=true`
- `POST /api/v1/alerts/events/:id/ack`

## Example rule
```json
{
  "name": "High temperature",
  "deviceId": "demo-device",
  "streamId": "temperature",
  "operator": ">",
  "threshold": 35,
  "severity": "warning",
  "cooldownSeconds": 300,
  "enabled": true
}
```

## Production follow-up
The beta alert store is process-memory. Stable v1.0 should persist rules/events in PostgreSQL, add authentication/RBAC, webhook delivery with retries, offline-device timers, and a background evaluation/cleanup worker.
