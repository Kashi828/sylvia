# SYLVIA v0.16 Beta — Bidirectional Device Communication

## Flow
1. Dashboard/integration POSTs `/api/v1/devices/:id/command` with the device Bearer token.
2. SYLVIA validates the device token and queues the command.
3. ESP32 SDK calls `Sylvia.run()` and polls `/api/v1/devices/commands/pending`.
4. Queued commands are delivered once and removed from the pending queue.
5. `Sylvia.onCommand(handler)` invokes firmware code with the command name and JSON payload text.

## Firmware
```cpp
void handleCommand(const String& command, const String& payload) {
  if (command == "restart") { /* restart device */ }
  if (command == "set_relay:on") { /* switch relay */ }
}

void setup() {
  Sylvia.begin(TOKEN, ssid, pass, SERVER);
  Sylvia.onCommand(handleCommand);
}

void loop() {
  Sylvia.run();
}
```

This is a beta polling transport. MQTT command subscriptions remain a later transport optimization; the application command contract can remain unchanged.
