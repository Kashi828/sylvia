# SYLVIA v0.44 — Secure Provisioning & Device Claiming

v0.44 hardens the bridge between a registered SYLVIA device and a physical NodeMCU.

## Flow
1. An authorized operator creates a short-lived provisioning claim for a registered device.
2. SYLVIA returns a one-time claim code and provisioning ID.
3. The provisioning client submits both to `/api/v1/devices/provision/claim`.
4. SYLVIA atomically consumes the claim and rotates the device credential.
5. The credential is returned once; store it securely on the device.
6. The device subsequently authenticates with its own bearer/MQTT credentials.

Claims expire after 15 minutes by default and cannot be reused.

## APIs
- `POST /api/v1/devices/provision` — create a claim (requires an existing device bearer in beta).
- `POST /api/v1/devices/provision/claim` — consume the one-time claim and receive a new device credential.

## Security notes
- Claim codes are compared with a timing-safe comparison.
- Device credentials are HMAC-SHA256 hashed server-side.
- Only the freshly rotated credential is returned to the claimant.
- Hosted MQTT should use TLS (typically port 8883) and CA validation.
- Never commit device credentials, claim codes, MQTT passwords, or CA/private keys to source control.
