# SYLVIA v0.39 Beta — Notification Provider Layer

## Goal
Introduce a vendor-neutral delivery layer so routed SYLVIA notifications can later reach email, mobile push, or other channels without changing the alert/routing core.

## Providers
- `console`: local development provider; always available.
- `webhook`: generic JSON HTTP/HTTPS delivery.
- `email-http`: generic HTTP adapter receiving `{type,email,from,to,subject,text,metadata}`.
- `push-http`: generic HTTP adapter receiving `{type,push,to,title,body,data}`.

The beta intentionally does not embed a specific SaaS provider. Hosted deployments should keep provider credentials/secrets outside the repository.

## Delivery behavior
- HTTP providers use POST + JSON.
- Requests time out after 8 seconds.
- A delivery record captures provider, status, HTTP status, error, and timestamp.
- Beta delivery history is bounded to 1,000 records in memory.
- Disabled or incomplete providers fail explicitly instead of silently succeeding.

## Test
Use `POST /api/v1/notifications/providers/test` with `{ "providerId": "..." }` to validate an adapter.
