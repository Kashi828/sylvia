# SYLVIA v0.38 Beta — Notification Routing Engine

## Goal
Turn v0.37 subscriptions into an active routing layer for the in-app notification inbox.

## Routing
Each notification is evaluated against enabled subscriptions for a `(userId, projectId)` scope. A notification is delivered to the scoped inbox when at least one enabled subscription matches its event kind and severity.

Supported kinds: `all`, `alert`, `delivery`
Supported severities: `all`, `info`, `warning`, `critical`, `success`, `error`

## API
- `GET /api/v1/notifications?userId=...&projectId=...` — returns only routed notifications.
- `GET /api/v1/notifications/routing?userId=...&projectId=...` — routing preview, matched counts and active subscriptions.
- Existing subscription CRUD remains available under `/api/v1/notifications/subscriptions`.

## Storage
Migration `006_notification_routing.sql` adds indexes for enabled subscription scopes and notification kind/severity queries. The beta continues to support the existing in-memory fallback.

## Future
The same routing decision can feed email, mobile push, SMS, and external integrations without changing the source event model.
