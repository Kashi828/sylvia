# SYLVIA v0.33 Beta — Alert Actions & Webhooks

Triggered telemetry alerts can now perform an optional outbound webhook action.

## Rule action
- `none` — create the alert event only.
- `webhook` — POST a JSON event to the configured HTTP/HTTPS URL.

## Payload
The webhook receives `type`, `event`, and a compact `rule` object. A test delivery can be generated from the Alerts workspace without waiting for telemetry.

## Delivery tracking
`GET /api/v1/alerts/deliveries` returns recent delivery attempts with status, HTTP status code, error and timestamp.

## Test
`POST /api/v1/alerts/rules/test` with `{ "id": "<ruleId>" }` queues a test webhook delivery.

Webhook requests use an 8-second timeout. Production deployments should place outbound webhook destinations behind an appropriate allowlist/network policy.
