# SYLVIA v0.40 Beta — Device Authentication & Token Hardening

v0.40 hardens the device credential boundary ahead of hosted NodeMCU testing.

## Changes
- Device bearer tokens are stored as HMAC-SHA256 hashes rather than plaintext in the server device registry.
- Token comparisons use constant-time comparison.
- API responses expose only a token fingerprint/preview, never the credential.
- Added `SYLVIA_DEVICE_TOKEN_SECRET` as the server-side signing/pepper secret.
- Added device token rotation endpoint:
  `POST /api/v1/devices/:id/token`
- Rotation returns the new token once; firmware should store it securely.
- Existing beta seed tokens remain accepted by their hashed seed values for local development compatibility.
- `validBearer()` now supports both Request and raw token inputs and optional device scoping, fixing the telemetry authentication contract.

## Environment
Set a strong random value in hosted deployments:

`SYLVIA_DEVICE_TOKEN_SECRET=<long-random-secret>`

Do not commit this value or expose it to browser code.

## NodeMCU implication
The NodeMCU will continue to send:

`Authorization: Bearer <device-token>`

The server now validates the credential against a one-way server-side hash.
