# SYLVIA v0.45 Beta — Real Hardware Telemetry

This milestone connects the ESP8266/NodeMCU SDK telemetry path to the server MQTT listener.

## Flow
NodeMCU → MQTT/TLS → SYLVIA MQTT subscriber → device-token validation → telemetry store → persistence/analytics/alerts.

## Telemetry payload
The ESP8266 SDK publishes JSON containing `channel`, `key`, `value`, and the device token over the authenticated TLS MQTT connection. The server validates the token against the device before accepting the sample.

## Heartbeat
The SDK publishes a retained heartbeat containing `online`, token, and firmware metadata. Valid heartbeats update fleet `lastSeen` and transport.

## Important
For hosted deployments use `mqtts://` with a real CA certificate on the NodeMCU. Do not use `setInsecure()` outside development.

## Test
1. Provision/claim a device and obtain its device token.
2. Configure the NodeMCU with Wi-Fi, broker hostname, port 8883, and CA certificate.
3. Run the ESP8266 example and call `Sylvia.virtualWrite(0, value)` periodically.
4. Verify the device becomes online in Fleet and telemetry appears in Telemetry Analytics.
5. Confirm an invalid token is rejected by the server subscriber.
