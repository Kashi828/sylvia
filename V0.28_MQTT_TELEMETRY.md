# SYLVIA v0.28 Beta — MQTT Telemetry Ingestion

v0.28 introduces a telemetry ingestion contract for real sensor data.

## Sample

```json
{
  "deviceId": "esp32-01",
  "streamId": "temperature",
  "key": "temperature",
  "value": 27.4,
  "timestamp": "2026-09-11T12:00:00.000Z"
}
```

## REST test endpoint

`POST /api/v1/telemetry`

`GET /api/v1/telemetry?deviceId=esp32-01&streamId=temperature`

## MQTT

The reserved topic is:

`sylvia/devices/<deviceId>/telemetry`

The payload uses the same application-level sample contract, allowing REST and
MQTT ingestion to share the same telemetry/history pipeline.

## Beta limitation

The telemetry store is currently in-process and capped at 5000 samples.
Production v1.0 should persist time-series data in PostgreSQL/TimescaleDB or
another durable telemetry backend and validate timestamps/ranges more strictly.
