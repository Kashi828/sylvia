# SYLVIA v0.29 Beta — Persistent Telemetry

v0.29 adds a PostgreSQL-backed telemetry persistence adapter.

## Behavior

When `DATABASE_URL` is configured, telemetry ingestion attempts to write to
the existing `telemetry_events` table. If the database is unavailable, the
beta falls back to the in-process telemetry store so local development remains
usable.

## New migration

`migrations/003_telemetry_metadata.sql`

Adds:
- `metadata JSONB`
- device/datastream/time index

## API

`POST /api/v1/telemetry`

`GET /api/v1/telemetry?deviceId=...&streamId=...`

The GET response includes a `storage` field indicating whether PostgreSQL or
the in-memory fallback is serving the request.

## Production note

v1.0 should make database persistence mandatory for production deployments,
add retention policies/partitioning, validate numeric ranges, and introduce
durable ingestion queues for high-volume telemetry.
